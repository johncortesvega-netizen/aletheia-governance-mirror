# ALETHEIA v0.1 — Logic Mapping Roadmap

Purpose: map the logic before adding major new app features.

## Current confirmed architecture

```text
User input
→ optional actor-bias reduction
→ review / stress test
→ repair questions
→ local witness receipt
→ human judgment
```

## Phase 1 — Baseline and safe language

Deliverables:

- `docs/baseline_v01.md`
- `docs/safe_language_map.md`
- `docs/eternal_baseline.md`
- baseline references in README / Why ALETHEIA
- tests for safe-language contract

Objective:

Keep ALETHEIA explicitly framed as a mirror, not an authority.

## Phase 2 — Boundary Cases Matrix

Map difficult edge cases before automation:

1. prediction versus free agency
2. voluntary protective limits
3. consent under pressure
4. basic-rights scarcity
5. reset-mechanism misuse
6. ambient capture / mass influence
7. spiritual claims without public evidence
8. neural data without consent
9. performative ethics without safeguards
10. ALETHEIA auditing itself

Output per case:

```text
Scenario:
Main risk:
Relevant guardrails:
Allowed responses:
Forbidden responses:
Failure type:
Recommended safeguard:
Human review note:
```

## Phase 3 — Failure classification

Every serious issue should be labeled as one or more of:

- Actor Failure
- Policy Failure
- Implementation Failure
- Data Failure

This prevents simplistic blame and keeps review precise.

## Phase 4 — Consent-Audit Engine

Questions:

- Can the person realistically say no?
- What happens if they refuse?
- Do they lose basic rights?
- Do they lose access to essential services?
- Is there social, economic, legal, or technical pressure?
- Can consent be withdrawn?
- Is refusal punished directly or indirectly?

Output:

- Green — refusal is realistic
- Yellow — refusal exists but has pressure
- Red — consent appears coerced or structurally forced

## Phase 5 — Mechanism-vs-Claim Scanner

Detect performative ethics.

Weak signal:

- values language without procedure
- broad claims of love, freedom, safety, justice, or dignity

Strong signal:

- appeal process
- audit trail
- time limit
- human review
- correction mechanism
- exit right
- evidence requirement
- conflict-of-interest rule
- independent oversight
- transparency process

## Phase 6 — Evidence Lab / Extraordinary Claim Protocol

Extraordinary claims are treated as unverified unless supported by public, testable, non-coercive evidence.

Personal meaning can be acknowledged.

Policy authority requires public review, evidence, transparency, appealability, accountability, and repair.

## Phase 7 — Self-audit mode

ALETHEIA must audit:

- its baseline
- prompts
- rubrics
- founder assumptions
- app wording
- receipt language
- scoring output
- doctrine references

Core test:

```text
No founder, architect, prompt, rubric, doctrine, model, document, output, or baseline is exempt from audit.
```

## Phase 8 — Deferred future concepts

Do not implement in v0.1:

- real Global ID
- real World Leader logic
- real 9k selection
- automatic deactivation
- central citizen database
- neural data
- memory extraction
- public ledger
- legal claims
- religious authority claims
- AI enforcement

These can remain conceptual until safety, consent, evidence, and review logic are mature.

## Success criteria

ALETHEIA v0.1 succeeds if it can:

1. audit documents in a repeatable structure
2. identify capture-risk signals
3. mark coercion and manipulation risks
4. check basic-rights risk
5. show evidence gaps
6. recommend safeguards
7. analyze boundary cases
8. classify failure modes
9. distinguish ethical language from mechanisms
10. self-audit without exempting the founder
11. avoid authority claims
12. keep human review central
