PATCH 72.9 MANIFEST - Evidence Lab Build/Explorer State Guard

Patch ID: 72.9
Patch name: Evidence Lab Build/Explorer State Guard
Owner/User: Johnny Cortes Vega
Project: ALETHEIA v1.0 - Governance Mirror

Purpose:
- Prevent Evidence Lab country/year selection and CSV downloads from feeling like a full rebuild/rescore of the uploaded master.
- Keep the active scored Evidence Lab table cached in session state until the active source table changes.
- Clarify upload diagnostics where individual source files can show 0 valid rows before the merged master exists.

Files changed:
- app.py
- tests/test_patch_72_9_evidence_lab_state_guard.py
- PATCH_72_9_MANIFEST.txt
- PATCH_72_9_RECOVERY_NOTE.md
- PATCH_STATUS.md
- docs/progress_database.md

Behavioral changes:
- Evidence Lab now creates a stable active-input signature from the active empirical table, source label, demo flag, and scored-master mode.
- If the signature matches the cached active table, Evidence Lab reuses `empirical_active_prepared_df` and `empirical_active_scored_all_df` from session state.
- Country/year selection and downloads no longer re-score the same active uploaded/generated master.
- The generated master CSV download uses an explicit key and explains that downloading exports the active session table, not a rebuild.
- Upload diagnostics now explain that individual files may show 0 valid country-year rows before merge; the merged master is the scoring source of truth.

Non-goals:
- No scoring formula change.
- No verdict-routing change.
- No 9k allocation formula change.
- No World Lens logic change.
- No receipt schema change.
- No Evidence Lab data model change.
- No public ledger, Global ID sync, central storage, or enforcement behavior.
